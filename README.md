# LePear

Визуальный редактор темы сайта на **shadcn/ui Base Nova**. Цвета, типографика и размеры применяются к живому предпросмотру. Тему можно сохранить в браузере, перенести через JSON и подключить к своему сайту через CSS.

MVP и дизайн MYT-16–MYT-26 приняты пользователем. Режимы YouTube MYT-28–MYT-32 приняты по отдельности; MYT-33 готовит общую ручную приёмку. Проверки выполняет пользователь.

## Запуск

Нужны Node.js, совместимый с Vite 8, и pnpm. Из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес из терминала Vite. По умолчанию порт 5173; при занятом порте он может измениться. Для восстановления локальных тем используйте тот же протокол, домен и порт.

| Команда        | Назначение                             |
| -------------- | -------------------------------------- |
| `pnpm dev`     | Сервер разработки                      |
| `pnpm build`   | Проверка TypeScript и сборка в `dist/` |
| `pnpm lint`    | Oxlint                                 |
| `pnpm preview` | Просмотр сборки после `pnpm build`     |

Отдельной команды тестов нет. Команды проверок приведены для ручного запуска пользователем, агентом на текущем этапе не выполнялись.

## Страницы

- `/` — лендинг со статичным макетом редактора, мобильным меню и FAQ.
- `/editor` — рабочий редактор, предпросмотр компонентов, локальные темы, импорт и экспорт.
- `/youtube` — сведения о ролике и подготовка MP4/WebM со звуком через локальный API; исходные аудиодорожки и MP3; отдельные субтитры VTT/SRT.
- `/contact` — демонстрационная контактная форма без отправки сообщений.

## Как создать тему

1. На `/editor` раскройте нужные группы. Их можно сворачивать независимо или все сразу; заголовки показывают текущие значения.
2. Выберите светлый или тёмный режим и пресет: «Лес», «Океан», «Слива» или «Графит». Цвета двух режимов независимы, пресет заменяет цвета только выбранного режима.
3. Измените акцент, поверхности, текст, границы и состояния. Поддерживаются picker и HEX; некорректный ввод не попадает в тему. Подсказки контраста не блокируют выбор.
4. Настройте шрифт, размер, насыщенности текста/заголовков и интервалы. Geist подключён локально с кириллицей; остальные семейства используют шрифты устройства и описанные fallback.
5. Выберите плотность и размеры. Это общие настройки для двух режимов. Высота контролов — минимальная; крупный текст и переносы могут увеличивать её.
6. Оцените широкий/узкий предпросмотр, кнопки, формы, таблицу, Select и Dialog. Действия примеров не меняют реальные данные.
7. В «Мои темы» создайте именованную копию. Рабочие изменения сохраняются автоматически, но именованная копия обновляется только кнопкой «Обновить копию».
8. Скачайте JSON для резервной копии или CSS для подключения к своему сайту.

Отдельные сбросы цветов, типографики и размеров сохраняют остальные параметры. «Сбросить всю тему» восстанавливает рабочую тему, не удаляя именованные копии.

## Сохранение и перенос

Рабочая тема и настройки панели сохраняются в `localStorage` (`lepear.workspace`). Библиотека вмещает до 20 именованных копий с уникальными названиями длиной 1–60 символов. Выбор другой копии заменяет рабочую тему; нужные варианты заранее сохраняйте отдельными копиями. Удаление копии оставляет рабочую тему в черновике.

JSON schema v2 содержит одну тему: обе палитры и общие настройки. Импортируйте файл или вставьте JSON, просмотрите параметры, затем нажмите «Применить тему». Невалидный импорт не меняет состояние. Максимальный размер — 1 МБ. Импорт не заменяет библиотеку именованных копий.

CSS содержит обе палитры, слой токенов **Tailwind v4** и дополнительные scoped-стили компонентов. Подключение требует обработки CSS сборкой, контейнера `.lepear-theme`, согласованных `data-theme`/класса `dark` и размещения порталов внутри контейнера. Шрифтовые файлы экспорт не включает.

[Минимальный пример и инструкция интеграции](examples/theme-integration/README.md).

Копирование CSS/JSON использует Clipboard API. Если оно недоступно, показывается поле ручного копирования; скачивание остаётся доступным.

## Ограничения MVP

- У редактора тем нет аккаунтов, серверного хранения и синхронизации между устройствами или вкладками. При работе нескольких вкладок последняя запись выигрывает.
- Данные зависят от браузера и origin; очистка данных сайта удаляет локальные темы. JSON резервирует одну тему, не всю библиотеку.
- При ошибке хранилища работа продолжается в памяти. Скачайте JSON и повторите сохранение после восстановления доступа.
- Повреждённые/устаревшие данные открываются с исходной темой и предупреждением. Старая запись не заменяется до явного действия пользователя. Автоматической миграции старых схем нет.
- Черновики ошибочного HEX, названия копий до сохранения и состояния демонстрационных форм не восстанавливаются.
- Системные шрифты и их начертания зависят от устройства; используются fallback.
- Подсказки контраста не заменяют полную проверку доступности, состояний и прозрачных наложений.
- Для собственных блоков используйте экспортированные токены или классы `lepear-stack`/`lepear-grid`. Сторонние компоненты могут требовать адаптации.

Размещение приложения согласуется отдельно. Для статического хостинга потребуется SPA fallback на `index.html`, чтобы прямые переходы на `/editor` и `/contact` работали. Публикация и выбор хостинга пока не выполнялись.

## Дизайн и анимации

Оформление построено на shadcn/ui Base Nova и Tailwind. Motion отвечает за короткие переходы и обратную связь; локальные React Bits Aurora и SpotlightCard — за отдельные акценты лендинга и контактов. Реестр ReUI подключён для дальнейшей работы, компоненты из него на этой итерации не добавлялись. Проект использует обычный Vite.

- [Итоговая ручная приёмка и карта эффектов — MYT-25](docs/design-acceptance.md).
- [Правила дизайна и описание этапов](docs/design-foundation.md).
- [Ранее подготовленный сценарий приёмки MVP](docs/manual-acceptance.md).
- [Подключение экспортированной темы](examples/theme-integration/README.md).

На dev-сервере доступна служебная страница /design-foundation; в production маршрут не регистрируется. Превью главной остаётся статичным макетом. В редакторской витрине нет декоративных React Bits: она показывает пользовательские токены. CSS/JSON не содержат анимации оболочки.

Уменьшение движения учитывается отдельно для Motion, CSS и React Bits. Отсутствие WebGL/эффекта не должно мешать содержимому и действиям. Сводный сценарий проверяет три страницы, мобильный вид, клавиатуру, обе палитры, сохранение, перенос и статичные fallback.

Проверки выполняет пользователь. Документы содержат инструкции, а не заранее успешные результаты. Дизайн MYT-25 и родительская MYT-15 приняты пользователем. Публикация согласуется отдельно.

## Выразительность дизайна — MYT-26

Согласованы исходная тёмная основа и типографика Arial Black / Geist. Композиция и движение обновлены без изменения модели пользовательской темы. [Описание реализации и ручная приёмка](docs/design-direction.md). Бумажный dev-образец отклонён и удалён.

## YouTube — MYT-27

Первая часть, MYT-28: страница /youtube, общая навигация, проверка/нормализация ссылки и вкладки Видео/Аудио/Субтитры. MYT-29 добавляет реальные метаданные, MYT-30 — скачивание видео со звуком. [Правила и ручная приёмка этапа](docs/youtube-development.md).

### Метаданные YouTube — MYT-29

Для получения данных дополнительно запустите отдельный локальный API. Нужен Node.js 22.18+:

```sh
pnpm youtube:setup
pnpm api
```

Vite запускается во втором терминале через pnpm dev; после изменения proxy перезапустите его. yt-dlp хранится в игнорируемой .tools/youtube, установщик сверяет официальный SHA-256 и не запускает бинарник. FFmpeg/ffprobe нужны для объединения видео и звука; автоматический установщик поддерживает Windows x64. Видео доступно в MYT-30, аудио — в MYT-31; субтитры — в MYT-32.

[Настройки API, ограничения и ручная приёмка](docs/youtube-api.md).

### Видео со звуком — MYT-30

Установите инструменты через pnpm youtube:setup-ffmpeg, перезапустите API. Во вкладке «Видео» выберите MP4/WebM, нажмите «Скачать»: готовый файл автоматически передаётся браузеру. Этапы и прогресс относятся к работе сервера; сохранение на устройство отображает браузер.

По умолчанию: ролик до 2 часов, файл до 1 ГиБ, одно задание, до 10 минут обработки и 15 минут хранения. Файлы лежат в игнорируемой .youtube-downloads, доступны только создавшей их браузерной сессии и удаляются по TTL, отмене или ошибке. Это локальный API; публичное размещение пока не реализовано.

[Запуск и сценарии ручной приёмки](docs/youtube-api.md). Проверки выполняет пользователь.

### Аудиодорожка — MYT-31

Во вкладке «Аудио» выберите исходную дорожку и формат файла. M4A/AAC и Opus сохраняются без перекодирования; MP3 создаётся через FFmpeg/libmp3lame с переменным битрейтом, без улучшения качества источника. Нажмите «Скачать» — результат автоматически передаётся браузеру. Можно отменить скачивание или конвертацию.

Используются те же лимиты, доступ по сессии и очистка, что у видео. Если отдельных аудиопотоков нет, режим объясняет ограничение. Скачивание видео для извлечения звука в этом этапе не используется.

### Субтитры — MYT-32

Во вкладке «Субтитры» выберите язык, авторскую или автоматическую дорожку YouTube, затем VTT/SRT. Метка возле формата показывает, будет ли он скачан напрямую или преобразован. «Скачать» автоматически передаёт готовый файл браузеру, «Отменить» прерывает обработку.

Видео и аудио не загружаются. Текст проверяется как UTF-8 с таймкодами, файл содержит язык и источник дорожки в имени. Без доступных дорожек скачивание отключено. Распознавание речи и создание перевода не выполняются. Лимит файла — до 16 МиБ и в пределах общего лимита файла; TTL и защита сессии общие с другими заданиями. После обновления кода перезапустите API и обновите страницу.

### Восстановление и общая приёмка — MYT-33

После изменения серверного кода остановите и заново запустите pnpm api. Обновление страницы Vite не перезапускает API. Полная установка инструментов на Windows x64: pnpm youtube:setup и pnpm youtube:setup-ffmpeg; API и Vite запускаются в разных терминалах.

При потере связи скачивание завершается ошибкой с попыткой отмены на сервере. После восстановления можно нажать «Скачать» повторно. При отмене кнопки блокируются до ответа API; при неизвестном состоянии сети отмена не гарантируется, работа ограничена серверным тайм-аутом. Если готовый файл исчез или срок хранения истёк, повторное нажатие позволяет создать его заново.

Смена ссылки/очистка/уход со страницы отменяют активную работу; «Очистить» заблокирована при получении метаданных. Закрытие/перезагрузка отправляет отмену через pagehide/keepalive, насколько позволяет браузер. После повторного открытия ничего автоматически не скачивается, история заданий не восстанавливается. Готовые серверные результаты остаются до TTL; начатое браузером сохранение идёт отдельно. Перезапуск API очищает результаты и обнуляет список заданий, пауза субтитров после 429 сохраняется.

[Единый сценарий ручной приёмки всех режимов](docs/youtube-acceptance.md). [Актуальный контракт API и ограничения](docs/youtube-api.md).

## Палитра горного заката — MYT-35

Оболочка использует глубокие сине-зелёные поверхности, янтарные действия и тёплый светлый текст по главному изображению. Значения централизованы в src/lib/shell-palette.ts и подключены как семантические Tailwind utilities. Палитра охватывает четыре страницы, меню/порталы, YouTube-прогресс и декоративные эффекты.

Рабочие темы редактора и экспорт не перекрашиваются. Иллюстрация на главной получает независимую демонстрационную тему. [Роли цветов и ручная приёмка](docs/sunset-palette.md). MYT-35 ожидает принятия; анимации и якоря — следующие отдельные задачи.

## Появление текста — MYT-36

Добавлены согласованные однократные появления заголовков/описаний на четырёх страницах с сохранением React Bits-акцентов. Текст плавно появляется один раз при входе в экран; reduced motion и отсутствие IntersectionObserver оставляют обычный видимый HTML. Статусы, ошибки, прогресс и пользовательское превью не получают декоративных появлений.

[Карта текста и ручная приёмка](docs/text-motion.md). Проверки выполняет пользователь.

## Появление блоков — MYT-37

Карточки, статичный макет, шаги, FAQ и служебные панели используют единое однократное появление. Соседние карточки имеют небольшой stagger; вложенный текст не дублирует вход родительского блока. Клавиатурный фокус немедленно показывает блок, reduced motion оставляет видимый HTML. Рабочая витрина редактора не анимируется.

[Карта блоков и ручная приёмка](docs/block-motion.md). Проверки выполняет пользователь.

## Aurora после перезагрузки — MYT-38

Монтирование Aurora отделено от паузы: при смене вкладки/видимости hero canvas сохраняется. Размер и первый кадр подготавливаются через useLayoutEffect; нулевой размер ожидает повторного измерения. Lazy-загрузка и WebGL имеют статичный fallback, ошибки чанка изолированы от контента.

[Изменения жизненного цикла и ручная приёмка](docs/aurora-lifecycle.md). Проверки выполняет пользователь.

## Плавные якоря — MYT-39

Ссылки на разделы и переходы внутри редактора используют общую прокрутку/фокус. Мобильное меню сначала закрывается; hash не перемонтирует header и формы. Повтор якоря и история браузера учтены. Reduced motion и «К содержимому» используют мгновенный переход.

[Поведение и ручная приёмка](docs/anchor-navigation.md). Проверки выполняет пользователь.
