# Конвертер музыки и изображений — MYT-40

Страница /converter использует общую оранжевую палитру, навигацию, Tailwind, shadcn/ui Base Nova и принятые анимации появления с reduced motion. Конвертируется один файл за раз; текстовые и офисные документы исключены по решению пользователя.

## Запуск

Нужны Node.js 22.18+ и FFmpeg/ffprobe:

    pnpm youtube:setup-ffmpeg
    pnpm api

Во втором терминале:

    pnpm dev

Если инструменты уже установлены, повторная установка не нужна. Используется общий установщик YouTube, но yt-dlp конвертеру не нужен. После изменений серверного кода/.env перезапустите API. После изменений порта перезапустите также Vite. Локальный API слушает 127.0.0.1; Vite проксирует /api. Это локальный режим, для публикации потребуется отдельная серверная конфигурация.

## Поддерживаемые сочетания

Внутри каждой строки любой исходный формат преобразуется в остальные целевые форматы этой же строки. Исходный формат не дублируется в списке.

| Категория             | Форматы                       |
| --------------------- | ----------------------------- |
| Музыка                | MP3, WAV, FLAC, OGG, M4A, AAC |
| Статичные изображения | PNG, JPEG, WebP, BMP          |

Дополнительные расширения: .wave → WAV, .oga/.opus → OGG, .jpeg/.jpe → JPEG. Для OGG поддерживаются входные Vorbis/Opus, для M4A — AAC/ALAC, для WAV — PCM. Многоканальное аудио, видео под видом M4A, GIF, SVG, анимированные PNG/WebP и документы не поддерживаются.

Каталог shared/converter-formats.json общий для интерфейса/API. Выбор по расширению предварительный: сервер проверяет фактические потоки/контейнер через FFprobe, сигнатуры изображений и признаки анимации. Переименование расширения не выполняет конвертацию.

### Аудио

- WAV: PCM signed 16-bit little-endian.
- FLAC: 16 бит.
- MP3: libmp3lame, VBR quality 2.
- OGG: Vorbis, quality 5.
- M4A: AAC 192 кбит/с в контейнере MP4/iPod.
- AAC: AAC 192 кбит/с в ADTS.

Входная частота 8–96 кГц, моно/стерео. WAV/FLAC сохраняют частоту и каналы. MP3/M4A/AAC используют ближайшую совместимую частоту до 48 кГц; OGG — исходную до 48 кГц. Фактические параметры показываются в результате. WAV/FLAC могут быть значительно больше исходника. Перекодирование не восстанавливает потерянное качество; MP3/OGG/AAC используют сжатие с потерями. Обложки и метаданные не переносятся.

### Изображения

PNG и WebP сохраняют альфа-канал; WebP кодируется lossless, JPEG — quality 2, BMP — BGR24. JPEG/BMP получают белый фон вместо прозрачности. Выходы 8-битные; сохранение HDR, ICC/EXIF и исходных метаданных не обещается. Используется штатная авторотация FFmpeg; выходные размеры сверяются с исходными с допуском поворота ширины/высоты. Новые размеры пользователь не задаёт.

Поддерживаются статичные изображения до заданного числа пикселей и до 32768 пикселей по стороне. Для целевого WebP каждая сторона — до 16383. Анимированные PNG/WebP отклоняются с объяснением, а не превращаются молча в один кадр. Размеры проверяются до декодирования FFmpeg; входы/выходы проверяются через FFprobe.

Технические справочники: [кодеки FFmpeg](https://ffmpeg.org/ffmpeg-codecs.html), [структура WebP и признаки анимации](https://developers.google.com/speed/webp/docs/riff_container).

## Пользовательский сценарий

1. Выберите файл. Показываются имя, размер и предварительный тип. Загрузка не начинается.
2. Список обновится под категорию файла. Для аудио по умолчанию WAV, для изображений — PNG; если это исходный формат, выбирается первый другой доступный.
3. Нажмите «Конвертировать». Загрузка показывает реальные переданные байты, аудиоконвертация — обработанную длительность. Анализ, проверка и конвертация картинки без выдуманного процента.
4. Результат автоматически передаётся браузеру. Основная кнопка становится «Скачать [формат]» и повторно выдаёт готовый файл.
5. «Отменить» прерывает передачу/дерево FFmpeg; следующий запуск дожидается подтверждения остановки предыдущего. Смена файла/формата после завершения сбрасывает результат и исключает выдачу старого файла.
6. По истечении срока повторное скачивание предлагает конвертировать заново.

## Лимиты и временные файлы

| Параметр .env                  | Значение по умолчанию                |
| ------------------------------ | ------------------------------------ |
| CONVERTER_MAX_INPUT_BYTES      | 104857600 (100 МиБ)                  |
| CONVERTER_MAX_OUTPUT_BYTES     | 536870912 (512 МиБ)                  |
| CONVERTER_MAX_DURATION_SECONDS | 1800 (30 минут аудио)                |
| CONVERTER_MAX_IMAGE_PIXELS     | 25000000 (25 Мп)                     |
| CONVERTER_UPLOAD_TIMEOUT_MS    | 120000 (2 минуты с создания задания) |
| CONVERTER_JOB_TIMEOUT_MS       | 300000 (5 минут на всё задание)      |
| CONVERTER_FILE_TTL_MS          | 900000 (15 минут после готовности)   |
| CONVERTER_CONCURRENCY          | 1                                    |
| CONVERTER_MAX_STORAGE_BYTES    | 1073741824 (1 ГиБ)                   |

Допустимые диапазоны определены в server/converter-config.mjs. CONVERTER_FFMPEG_PATH / CONVERTER_FFPROBE_PATH необязательны, по умолчанию используются инструменты YouTube. Порт и Origin общие через YOUTUBE_API_PORT / YOUTUBE_ALLOWED_ORIGINS, но задания/лимиты/файлы конвертера независимы.

Медиаданные загружаются и выдаются потоками, целиком в память не читаются. Проверка блоков PNG/WebP использует адресное чтение малых заголовков. До аудиоконвертации WAV/FLAC и обработки изображений консервативно оценивается выходной размер (для картинок 6 байт/пиксель + 64 КиБ), поэтому при малом лимите даже хорошо сжимаемое изображение может быть отклонено заранее; запись ограничена FFmpeg и дополнительным наблюдением за размером файла. Перед запуском проверяется дисковый бюджет с запасом под максимальный вход/выход и свободное место с резервом 128 МиБ. Не более 20 удерживаемых записей и 10 новых запросов в минуту с адреса.

Файлы изолированы в игнорируемой .converter-files/UUID. Сервер сам формирует пути, очищает имя скачивания и выдаёт правильный MIME. Доступ только с HttpOnly SameSite cookie владельца; одного ID недостаточно. Исходник удаляется после успеха; при ошибке/отмене удаляется весь каталог задания. Готовый файл доступен до TTL, фоновая очистка выполняется каждые 10 секунд. Уже начатой выдаче разрешено завершиться, после неё отложенное удаление продолжается. При старте API старые UUID-каталоги удаляются под блокировкой хранилища.

При уходе/закрытии/перезагрузке отправляется отмена активного задания best effort; при потере сети действует серверный таймер. Автовозобновления, хранения выбранного файла в браузере и восстановления результата после перезапуска API нет. Завершённые результаты после ухода остаются только до TTL.

## Ручная приёмка пользователем

Проверки агентом не запускались. Проверьте последовательно:

- Выбор разных аудио/картинок: правильный список, отсутствие исходного формата, смену целевого формата без старого результата, длинное/кириллическое имя, повторный выбор того же файла, неподдерживаемые документы.
- Аудио в каждом выходном формате: воспроизведение, расширение/MIME, длительность, частоту и моно/стерео. Отдельно FLAC/OGG/M4A/AAC как источники.
- PNG/JPEG/WebP/BMP в каждом выходном формате: открытие, размеры, прозрачный PNG → WebP и PNG → JPEG/BMP с белым фоном, JPEG с ориентацией EXIF.
- Анимированные PNG/WebP, превышение числа пикселей, слишком широкую картинку → WebP, повреждённые файлы и ложное расширение: понятная ошибка.
- Двойное нажатие, отмену при передаче/конвертации, повтор после отмены, уход/перезагрузку, отсутствие API/инструментов, ограничения размера/времени/места.
- Повторное скачивание до/после TTL, очистку файлов, изоляцию другой сессии.
- Мобильные 320/390 px, клавиатуру, reduced motion, навигацию/footer; редактор и три сценария YouTube.

Для короткой ручной проверки TTL можно временно поставить CONVERTER_FILE_TTL_MS=60000 и перезапустить API. Не заполняйте диск вручную ради проверки ограничений.
