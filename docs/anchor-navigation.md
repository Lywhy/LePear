# Якорная прокрутка — MYT-39

Единая прокрутка оболочки через anchor-scroll и useSiteScroll. Палитра, принятые анимации и данные редактора/YouTube не изменены.

## Поведение

- Hero «Как это работает» использует React Router Link, поэтому нативный href не прыгает к hash перед программной прокруткой.
- Ссылки footer и мобильного меню ведут к тем же секциям с hash. Повтор того же адреса вызывает позиционирование без лишней копии history entry.
- focusAndScrollTo переводит фокус через preventScroll, затем на следующем кадре выполняет smooth scrollIntoView. Это позволяет появляющемуся блоку раскрыться от фокуса до измерения его позиции.
- Для features/how-it-works/faq установлен scroll-mt-24; панели редактора сохраняют свои scroll-mt-24. Они оставляют место над целевой секцией.
- Кнопки перехода внутри редактора используют тот же helper, сохраняя существующие id и рабочее состояние.
- «К содержимому» переводит фокус/прокрутку мгновенно, не создавая лишнюю запись hash.
- При prefers-reduced-motion все якорные переходы мгновенные.

## Маршруты и история

useSiteScroll ждёт готовности шрифтов, если они загружаются, и два кадра для фиксации вёрстки. Новая навигация отменяет прежние запланированные переходы и останавливает предыдущую smooth-прокрутку.

При обычном переходе к hash выполняется плавная прокрутка. При первом прямом открытии URL с hash выполняется позиционирование без дополнительного длинного пролистывания страницы. Первое открытие без hash не принуждает к верху, позволяя браузеру восстановить исходное положение при загрузке.

Для клиентского back/forward позиции хранятся в памяти по location.key (до 100 записей), восстановление выполняется мгновенно без конкурирующего нативного восстановления. Если сохранённой позиции нет, используется hash либо начало новой страницы. Неизвестный/повреждённый hash не вызывает исключения.

Header теперь имеет key только по pathname: hash не перемонтирует шапку. Контент также сохраняет key по pathname, поэтому hash не сбрасывает формы, текстовые эффекты или задание YouTube. Переход на другую страницу сохраняет прежнюю семантику смены маршрута.

## Мобильное меню

Обычное нажатие на ссылку сначала закрывает Sheet, затем onOpenChangeComplete выполняет переход. Возврат фокуса на кнопку меню в этом случае подавляется: назначением фокуса становится целевая секция/страница. При закрытии крестиком/Escape обычный возврат фокуса сохраняется. Ctrl/Cmd/Shift/Alt-клики не перехватываются.

Ссылки остаются настоящими Link/anchor. Новых CSS-правил scroll-behavior, которые конкурировали бы с JS, нет.

## Ручная приёмка

1. На главной нажать «Как это работает»: нет начального резкого прыжка или второго скролла, целевой блок виден с отступом.
2. Проверить все три footer-якоря с главной и с /editor, /youtube, /contact.
3. Уйти от целевой секции вручную и снова нажать ссылку на тот же hash: плавный переход повторяется, header не дублируется.
4. В мобильном меню выбрать раздел текущей главной и другой страницы. Меню закрывается до прокрутки, фокус не возвращает экран к шапке.
5. Проверить Back/Forward между якорями и страницами, включая исходное положение вверху. Открыть /#faq напрямую и обновить страницу.
6. В редакторе перейти к настройкам/превью/переносу. Выбранная тема, раскрытые группы и данные не меняются.
7. Tab → «К содержимому»: мгновенный перенос фокуса. Обычные якоря доступны Enter; фокус целевой секции соответствует назначению.
8. Включить reduced motion: все переходы мгновенные. Проверить 320/390 px, отсутствие перекрытия заголовка и горизонтального скролла.
9. Нажать другой якорь во время плавной прокрутки: прежняя цель не должна позднее вернуть экран назад.
10. Вставить некорректный/неизвестный hash: страница остаётся работоспособной, без исключения.

Сборка, линтер, тесты, API, браузерные/визуальные проверки агентом не запускались. Результаты не проставлены. MYT-39 и родительская MYT-34 закрываются после общего принятия пользователем.
