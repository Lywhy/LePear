# Правила дизайна и описание этапов — MYT-16–MYT-25

Актуальные правила и история реализации дизайн-итерации. Единая карта эффектов и итоговый сценарий находятся в [ручной приёмке MYT-25](design-acceptance.md). Записи отдельных этапов ниже описывают их реализацию, не результаты текущих проверок. Рабочий стек — обычный Vite, Motion установлен пользователем; импорты анимаций из motion/react.

## Роли библиотек

- shadcn/ui Base Nova: семантика и поведение кнопок, форм, Accordion, Select и Dialog.
- Tailwind: статичное оформление, адаптивность, focus/hover/disabled.
- Motion: появление блоков, короткая обратная связь, переходы страниц/состояний.
- React Bits TS-TW: отдельные визуальные акценты маркетинговых страниц. Подключаются по одному в задаче, где применяются; текущая основа не устанавливает каталог эффектов.

## Движение

`AppMotion` подключён над маршрутизатором в `src/main.tsx`: `MotionConfig reducedMotion="user"`, общий переход 160 мс. Наличие провайдера само по себе не анимирует страницы.

`src/lib/motion-presets.ts` задаёт:

- отклик — 160 мс;
- появление — 320 мс;
- выходящие страницы удаляются сразу, отдельный exit-переход не используется;
- easing — `[0.22, 1, 0.36, 1]`.

`Reveal` перемещает блок на 8 px к финальной позиции. Текст виден с первого кадра (`opacity: 1`), без задержки доступности. `feedbackMotion` даёт короткий сдвиг 2 px для сообщения. При reduced motion оба возвращают статичное появление с длительностью 0. Неизвестная настройка трактуется консервативно как reduced motion.

Не задавать Tailwind `transition-all`/`transition-transform` на узле, чей transform управляется Motion. Для обычной смены цвета на кнопке достаточно Tailwind; не добавлять второй обработчик Motion для того же эффекта. Не анимировать поле на каждую введённую букву, не перемонтировать форму ради анимации и не заставлять пользователя ждать появления действия. Скрытые выходящие экраны не должны оставаться доступными с Tab.

Не возвращать hover-фон/подчёркивание заголовков групп настроек. Для них сохраняется только видимый keyboard focus. Превью главной остаётся статичным макетом, работа с темой — на `/editor`.

## Политика декоративных циклов

`useDecorativeMotion(ref)` разрешает декоративный эффект только при выполнении всех условий:

1. Пользователь не просит уменьшить движение.
2. Область видна не менее чем на 10%.
3. Вкладка видима.
4. Ширина не менее 768 px и устройство имеет точный указатель.

При false Aurora размонтируется, оставляя статичный пейзаж. SpotlightCard сохраняет DOM карточки и отключает effect через effectsEnabled=false с очисткой RAF/слушателей; его собственные проверки видимости останавливают цикл вне viewport/скрытой вкладки. На карточках возможностей главной reduced motion отключает эффект, touch не активирует реакцию указателя. Просто скрыть работающий canvas через CSS недостаточно. Декоративные слои aria-hidden, не получают фокус и не перехватывают ввод.

MotionConfig управляет Motion-анимациями, а не произвольными RAF, CSS и canvas. Поэтому React Bits и другие фоновые циклы должны использовать эту явную политику. Существующие shadcn/CSS-анимации адаптируются в своих задачах, не считаются автоматически отключёнными одним провайдером.

## Страница образцов для пользователя

На dev-сервере вручную откройте `/design-foundation` по тому же адресу/порту, что приложение. Страница загружается лениво и зарегистрирована только при `import.meta.env.DEV`; в production маршрут не регистрируется и попадает под обычный fallback приложения. Ссылки на неё в пользовательской навигации нет.

Образцы: палитра и текст, primary/secondary/disabled кнопки, короткий отклик, повторяемый Reveal, статичный градиент и индикатор разрешения фоновых эффектов. Это не новый рабочий сценарий продукта и не автоматическая проверка.

Ручная приёмка:

1. Оценить палитру, текст, поверхности и кнопки на широком и узком экране; Tab показывает focus, disabled не действует.
2. Нажать «Повторить появление»: блок коротко перемещается, текст сразу виден. Кнопки действий меняют демонстрационное сообщение.
3. Включить системное/эмулируемое `prefers-reduced-motion`: индикатор обновляется, Reveal и отклик становятся статичными, разрешение фонов выключается.
4. Изменить ширину до мобильной/desktop, прокрутить область: индикатор фоновой политики реагирует. Сам фон на странице образцов всегда статичный.
5. Открыть `/`, `/editor`, `/contact`: в этой задаче их оформление не перерабатывалось; глобальный MotionConfig не должен менять данные темы/копий или добавлять интерактивность главному макету.

Сборка, линтеры, тесты, браузерная/визуальная проверка агентом не выполнялись. Страница и правила переданы для ручной приёмки, успешная проверка не заявляется.

Документация: [MotionConfig](https://motion.dev/docs/react-motion-config), [useReducedMotion](https://motion.dev/docs/react-use-reduced-motion), [Motion + Tailwind](https://motion.dev/docs/react-tailwind), [React Bits](https://reactbits.dev/get-started/introduction).

## Общая навигация и переходы — MYT-17

На `/`, `/editor` и `/contact` используется общий `SiteLayout`: шапка высотой от 80 px, единые контейнеры и ссылки, активная страница и footer. Логотип, ранее удалённый пользователем, не возвращается. Контент страниц, макет главной и данные темы сохраняют назначение; переработка hero/редактора/контактной формы относится к следующим задачам.

Desktop-навигация: Главная / Редактор / Обратная связь. На мобильном шапка содержит путь на главную, основное действие и кнопку меню. Меню использует установленный shadcn Sheet на Base UI: модальный фокус, Escape, явная русская кнопка закрытия, `aria-expanded` и `aria-controls`. Внутри меню есть ссылки страниц и разделов главной. При переходе оно размонтируется вместе с заголовком текущего маршрута; при расширении окна до desktop закрывается через media-query listener. Reduced-motion варианты отключают движение панели и переход overlay. Focus остаётся видимым.

Контент при смене pathname получает только краткий переход opacity 0.92 → 1 (320 мс) без transform, чтобы не создавать новый контекст для fixed-порталов. Нет AnimatePresence и задержки ухода: старое дерево немедленно удаляется, поэтому не остаётся скрытого фокусируемого экрана. Хеш-переходы не перемонтируют редактор ради анимации. Reduced motion/неизвестная настройка показывают контент сразу.

`SiteLayout` задаёт document.title. При переходе между страницами прокручивает наверх и переносит фокус на контейнер содержимого после первого кадра. Для хеш-ссылок на разделы главной прокручивает к элементу и переводит фокус туда; есть общая skip-ссылка «К содержимому». Якорные ссылки используют обычную прокрутку без принудительного smooth, включая reduced motion. Данные автосохранения/библиотеки не меняются навигацией. Ограничения недоступного localStorage остаются прежними.

Ручная приёмка:

1. На трёх страницах сравнить высоту/отступы шапки, активный пункт и footer, ссылки главная/редактор/контакты. Проверить узкий экран 320/390 px и desktop.
2. На мобильном открыть меню: Tab остаётся внутри модального меню, Escape/кнопка закрытия возвращают фокус. Выбор ссылки закрывает панель. Расширить окно до desktop при открытом меню.
3. Через меню/footer перейти к Возможностям/Шагам/FAQ с другой страницы: нужный раздел должен быть виден, фокус — на нём. Проверить skip-ссылку и Back/Forward.
4. Поменять тему, создать копию и перейти редактор → контакты → редактор: автосохранённые параметры/копии/раскрытые группы должны восстановиться.
5. Проверить быстрые переходы, отсутствие перекрытия новым/старым экраном и скрытых Tab-целей. Открытый Select/Dialog редактора не должен зависать после ухода со страницы.
6. Включить reduced motion: переход страницы и движение мобильной панели отключены, навигация доступна сразу.

Сборка, линтеры, тесты и браузерная/визуальная проверка агентом не запускались. Новых зависимостей и CSS-файлов не добавлено. Результаты приёмки ожидаются от пользователя.

## Первый экран лендинга — MYT-18

Первый экран вынесен в `LandingHero`. Сохранены пейзаж и природная палитра; уточнены описание редактора, основное действие «Создать тему», ссылка на шаги работы и преимущества (без регистрации, локальные темы, CSS/JSON). Метка и подписи используют читаемый размер 14 px. Макет редактора ниже остаётся статичным, без новых фокусируемых контролов.

Через shadcn MCP просмотрены Aurora-TS-TW и BlurText-TS-TW и получена команда добавления Aurora. Поскольку Aurora не требует дополнительных пакетов, её исходник получен непосредственно из официального JSON реестра и размещён в `src/components/react-bits/aurora.tsx`. Сохранены источник и лицензия React Bits в соседнем `LICENSE`. Локальная адаптация: при `mouseInteraction=false` не подписываться на pointer-события окна. Cleanup исходного компонента отменяет RAF, отключает observers/слушатели и освобождает WebGL-ресурсы.

Hero использует один Aurora-фон: медленная скорость 0.35, один слой, DPR 1, без вступительного эффекта и реакции на курсор. Lazy-загрузка происходит только при разрешении `useDecorativeMotion`: desktop с точным указателем, видимая вкладка/область и reduced motion выключен. При запрете компонент размонтируется; пейзаж и затемнение постоянно присутствуют как fallback. Если WebGL2 недоступен или шейдер не создаётся, статичная основа остаётся. Декоративные слои aria-hidden и pointer-events-none.

Для заголовка/CTA/макета использовано обычное появление Motion на 8 px/320 мс без размытия и задержек. BlurText не установлен, чтобы не снижать читаемость и не добавлять второй эффект к заголовку. Заголовок — один h1, текст доступен с первого кадра. Reduced motion делает появления статичными. Основные страницы редактора/контактов, модель и формат экспорта не менялись. В шапку отдельная кнопка редактора не возвращалась.

Ручная приёмка:

1. На `/` оценить первый экран и соотношение текста/CTA/макета, размер подписей и читаемость на 320/390 px и desktop.
2. «Создать тему» ведёт в редактор; «Как это работает» — к шагам на главной. Проверить клавиатуру/focus и отсутствие активных настроек в макете.
3. На desktop при разрешённом движении Aurora мягко движется, текст не перекрыт и доступен сразу; вступление заголовка/CTA/макета короткое.
4. Включить reduced motion, сузить окно до мобильного или переключить вкладку/прокрутить hero из области видимости: динамический фон должен отсутствовать, статичная основа остаётся.
5. При недоступном WebGL2 первый экран остаётся читаемым с пейзажем. При возврате на страницу не остаются старые canvas/слушатели.

Сборка, тесты, линтеры и браузерная/визуальная проверка агентом не выполнялись. Установка npm-пакетов не запускалась.

Доработка MYT-18 по замечанию пользователя: `settingsRef.current` обновляется в useEffect вместе с пробуждением рендера, а не во время React render. При cleanup WebGL-контекст принудительно теряется только для уже отсоединённого canvas: повторный запуск эффектов StrictMode на том же DOM-узле должен иметь возможность использовать контекст снова. Яркость Aurora увеличена до 1, общая непрозрачность до 85%, палитра стала контрастнее. Глобальное затемнение помещено под Aurora, поверх неё осталось локальное радиальное затемнение для текста. Условия отключения фона сохранены.

Для повторной ручной приёмки полностью перезагрузите страницу (старый canvas мог уже потерять контекст), откройте hero на desktop при выключенном reduced motion и оцените свечение по краям/сверху, читаемость текста и предупреждение refs. На мобильном/reduced motion по-прежнему статичный фон. Из React Bits в этом этапе установлен Aurora; SpotlightCard относится к MYT-19. Линтер, сборка и браузер агентом не запускались.

## Возможности, шаги, FAQ и финальный CTA — MYT-19

Блоки после статичного макета вынесены в `landing-sections.tsx`. Возможности представлены тремя карточками: цвет, типографика, размеры. Визуальные примеры остаются иллюстрациями, а явно подписанные ссылки ведут в редактор. Добавлена сводка двух независимых режимов, локальных копий и JSON. Первому экрану, рабочему редактору и данным тем эта задача не меняет поведение.

Карточки используют React Bits `SpotlightCard-TS-TW`, просмотренный через shadcn MCP и полученный из официального JSON реестра. Компонент не требует дополнительных пакетов; исходник хранится в `src/components/react-bits/spotlight-card.tsx`, лицензия — в соседнем `LICENSE`. Локальные адаптации:

- Параметры ref обновляются только в useEffect, не во время React render.
- Проп effectsEnabled отключает движок и подписки при reduced motion; состояние получается через Motion useReducedMotion у потребителя.
- События касания/пера не двигают spotlight. Ambient и flare в карточках отключены; автоматического непрерывного движения нет.
- Hover даёт мягкое лаймовое свечение и подсвеченную кромку. Keyboard focus на ссылке также задаёт центр свечения; статичная рамка focus-within остаётся и без эффекта.
- RAF не работает в скрытой вкладке/невидимой области; cleanup удаляет listeners/observer/RAF и обнуляет прозрачность декора.
- Базовый padding сделан переопределяемым, чтобы иллюстрация и текст карточки имели собственные отступы. Градиенты — динамические inline-значения компонента; оформление страницы остаётся Tailwind.

Шаги: выбрать основу → настроить интерфейс → сохранить вариант → перенести в проект. ScrollReveal использует начальное visible-состояние и короткое перемещение 8 px/320 мс при первом входе в область видимости (`once`). Нет initial opacity 0, задержек, повторного скрытия текста и постоянного проигрывания при прокрутке. При reduced motion элемент статичен.

FAQ на shadcn Accordion обновлён под принятый MVP: автосохранение/до 20 копий, независимые палитры, Tailwind v4 и подключение CSS/шрифтов/порталов, JSON schema v2 и ограничение 1 МБ, отсутствие аккаунтов и синхронизации. Сохранена явная пометка демонстрационной контактной формы. Высота раскрывается только механизмом Accordion; Motion-анимация сверху не добавлена. Reduced-motion классы отключают анимацию/transition FAQ.

Финальный CTA согласован с карточками и ведёт в редактор. Общий footer MYT-17 используется без дублирования. В шапку удалённая кнопка редактора и hover групп настроек не возвращаются.

Ручная приёмка:

1. На `/` прокрутить к возможностям, оценить иллюстрации/текст/ссылки и свечение при мыши. Tab к ссылкам внутри каждой карточки: focus и подсветка доступны без hover.
2. На touch/мобильном и при reduced motion карточки читаемы статично, действия доступны. Проверить узкие 320/390 px и desktop.
3. Пройти четыре шага: текст виден до анимации, появление короткое и не повторяется при прокрутке назад-вперёд.
