# Стабильность Aurora — MYT-38

Стабилизирован жизненный цикл декоративного фона hero. Палитра, текстовые/блочные появления и работа остальных страниц сохранены. Браузерные прогоны не выполнялись; ниже изменения исходников и сценарии для пользователя.

## Что меняется

Раньше один флаг useDecorativeMotion управлял и правом показывать эффект, и его текущей активностью. Когда вкладка скрывалась либо hero выходил из viewport, Aurora размонтировалась, а при возвращении заново загружалась/создавала WebGL-ресурсы.

useDecorativeMotionState теперь различает supported (desktop с fine pointer и разрешённой анимацией) и active (дополнительно видимость hero/документа). Hero монтирует Aurora по supported, а движение регулирует paused. Смена видимости больше не уничтожает canvas. Другие декоративные компоненты сохраняют прежний active-only интерфейс useDecorativeMotion.

Lazy-загрузка сохранена внутри отдельного Suspense. Под canvas всегда есть статичный градиент в принятой палитре и исходное изображение. DecorativeBoundary ограничивает ошибку необязательного lazy-чанка областью декорации: контент страницы продолжает отображаться.

## Размер, первый кадр и восстановление

- Настройки renderer и инициализация перенесены в useLayoutEffect: измерение и первый кадр выполняются до отрисовки подготовленного canvas.
- Нулевой размер не подменяется фиктивным 1×1. При нулевом контейнере кадры остановлены, canvas прозрачен, fallback виден.
- ResizeObserver и window resize повторяют измерение; размер backing buffer меняется только при реальной необходимости.
- Canvas становится видимым после drawArrays с ненулевым размером; CSS utility transition-opacity сглаживает появление.
- При скрытии/выходе из viewport RAF останавливается, при возвращении размер обновляется и отрисовка возобновляется без скачка времени.
- Обработчики contextlost/contextrestored устанавливаются до создания shader program. При потере контекста показывается fallback, восстановление пересоздаёт собственные ресурсы.
- Освобождаются частично созданные shader/program/buffer/VAO, наблюдатели и слушатели. Cleanup не вызывает искусственную потерю WebGL-контекста.
- При paused/reduced motion не создаётся непрерывная цепочка неподвижных кадров. Один renderer владеет одной RAF-цепочкой.

useLayoutEffect здесь — часть исправления измерений и первого кадра, а не единственная мера.

## Ручная приёмка

1. На desktop с fine pointer и отключённым reduced motion выполнить обычную и полную перезагрузку главной несколько раз. Aurora должна появляться после загрузки чанка, до неё — оформленный fallback.
2. Перейти с другой страницы на главную и обратно. Не должно появляться дубликатов canvas и новых предупреждений о потере WebGL.
3. Прокрутить hero за экран, вернуться, переключить вкладку браузера и вернуться. Эффект возобновляется без пустого состояния.
4. Обновить страницу со скроллом ниже hero, затем прокрутить наверх. Проверить корректный размер первого видимого кадра.
5. Менять размер окна/масштаб, пересечь границу desktop/mobile. Эффект не должен зависнуть с нулевым или неверным размером.
6. Проверить мобильные 320/390 px, reduced motion и недоступный WebGL: статичный фон и контент остаются доступны, canvas не обязателен.
7. Если пользователь моделирует потерю/восстановление контекста либо ошибку загрузки чанка: ожидать fallback и сохранение содержимого; после восстановления контекста — повторный запуск renderer.
8. Проверить, что типографика, принятые появления блоков, редактор и YouTube работают по прежним правилам.

Сборка, линтер, тесты, API, браузерные/визуальные проверки агентом не запускались. Нельзя считать этот документ подтверждением успешных результатов. После принятия MYT-38 следующий issue — MYT-39 (якорная прокрутка).
