# YouTube API: запуск, контракт и ограничения

## Локальный запуск

Нужны Node.js 22.18+ и pnpm. API — отдельный Node-процесс без новых npm-зависимостей, worker запускает локальные yt-dlp и FFmpeg/ffprobe.

```sh
pnpm install --frozen-lockfile
pnpm youtube:setup
pnpm youtube:setup-ffmpeg
pnpm api
```

Во втором терминале: pnpm dev. Открыть /youtube по адресу Vite. После изменения серверных файлов остановить pnpm api и запустить заново; Vite HMR не обновляет API. После изменения proxy/.env перезапустить API и Vite.

Установщики загружают официальные релизы, сверяют SHA-256, сохраняют бинарники/версию в игнорируемой .tools/youtube и не выполняют бинарники. Установщик FFmpeg поддерживает Windows x64; на других платформах нужны собственные FFmpeg/ffprobe. Перед обновлением инструментов остановить API. Опциональные пути: YOUTUBE_YTDLP_PATH, YOUTUBE_FFMPEG_PATH, YOUTUBE_FFPROBE_PATH; абсолютные либо от корня проекта.

Настройки перечислены в .env.example. Скопировать в .env при необходимости, сохранив существующие параметры. Секреты и локальные пути не коммитить. Node используется также для YouTube EJS; отдельный Deno не нужен.

API слушает 127.0.0.1:8787; Vite/preview проксируют /api. Для просмотра с телефона полный origin компьютера должен присутствовать в YOUTUBE_ALLOWED_ORIGINS. Host и Origin проверяются. Это локальная архитектура; публичное размещение/авторизация пользователей не реализованы.

## Возможности

- Видео: выбранный MP4/WebM, совместимая звуковая дорожка при необходимости, объединение FFmpeg без перекодирования. ffprobe проверяет видео, звук, длительность и размер.
- Аудио: отдельный аудиопоток, исходный M4A/AAC или Opus без перекодирования; MP3 через libmp3lame VBR q=2. Качество не увеличивается. При отсутствии отдельного аудиопотока извлечение из видео не выполняется.
- Субтитры: выбранные язык и авторский/автоматический источник, VTT/SRT напрямую или с конвертацией FFmpeg. Только текст, без загрузки медиа. Распознавание речи и создание перевода не выполняются.

«Лучшее качество» по умолчанию разрешается в конкретный доступный поток: максимальные разрешение/FPS с совместимым звуком для видео, объявленный битрейт для аудио. Лимиты продолжают действовать; слишком большой результат требует выбора меньшего качества.

Ссылка общая: для аудио/субтитров не нужно сначала скачивать видео. Получение метаданных не начинает скачивание. «Скачать» запускает работу и автоматически передаёт готовый файл браузеру. Повтор того же готового результата проверяет его доступность и скачивает без новой обработки.

## Лимиты по умолчанию

| Параметр                              | Значение                                                |
| ------------------------------------- | ------------------------------------------------------- |
| Длительность ролика                   | до 2 часов                                              |
| Метаданные: сервер / клиент           | 45 / 55 секунд                                          |
| Одновременные запросы метаданных      | 2                                                       |
| Метаданные + создание заданий         | 10 запросов в минуту на сетевой адрес                   |
| JSON запроса / вывод метаданных       | 4 КиБ / 8 МиБ                                           |
| Активные задания всех режимов         | 1, без очереди                                          |
| Готовое видео/аудио и исходные потоки | до 1 ГиБ                                                |
| Один файл субтитров                   | min(общий лимит, 16 МиБ)                                |
| Время задания целиком                 | до 10 минут                                             |
| Хранение готового результата          | 15 минут                                                |
| Бюджет временного хранилища           | 4 ГиБ                                                   |
| Записи заданий                        | до 20                                                   |
| Запрос/чтение текста субтитров        | 30 секунд                                               |
| Пауза субтитров перед запросом        | 5 секунд                                                |
| Пауза после HTTP 429                  | минимум 5 минут, учитывает больший Retry-After до суток |

При создании задания резервируется бюджет исходных потоков и результата: 2 × лимит файла + 16 МиБ, плюс проверка 128 МиБ свободного места. Фактический объём отслеживается каждые 400 мс; небольшое превышение между измерениями возможно. Это программные ограничения, не квота ОС. Опрос статуса не расходует лимит создания.

Неизвестная длительность блокирует скачивание видео/аудио. Для субтитров размер ограничивается также при потоковой записи. Готовый результат проверяется до выдачи. Настройки проверяются при старте; произвольные CLI-флаги не принимаются.

## API v1

Все запросы идут через /api. JSON содержит apiVersion: 1.

GET /api/health — возможности, лимиты и наличие инструмента. Это не проверка обращения к YouTube или воспроизведения.

POST /api/youtube/metadata, Content-Type application/json:

```json
{ "url": "https://www.youtube.com/watch?v=VIDEO_ID_11" }
```

Ответ: video (id/url/title/channel/duration/thumbnail), formats.video, formats.audio, subtitles, warnings, capabilities.downloads. Размер потока — null либо {bytes, approximate}; он не равен будущему объединённому/преобразованному файлу. Signed URLs, cookies и сырой вывод CLI клиенту не выдаются.

GET /api/youtube/session — HttpOnly, SameSite=Strict cookie lepear_youtube с криптографическим секретом и Path=/api/youtube; capabilities.audioDownloads/subtitleDownloads позволяют распознать старую версию API.

POST /api/youtube/jobs:

```json
{
  "kind": "audio",
  "videoId": "VIDEO_ID_11",
  "formatId": "251",
  "outputFormat": "mp3",
  "requestId": "32 hex-символа"
}
```

Поля режимов:

| kind      | Выбор                                                            |
| --------- | ---------------------------------------------------------------- |
| video     | formatId исходного видеопотока                                   |
| audio     | formatId отдельного аудио; outputFormat=original или mp3         |
| subtitles | formatId=vtt или srt; subtitleTrackId=manual:ru или automatic:ru |

Сервер повторно проверяет принадлежность дорожки ролику. Повтор одного requestId в пределах сохранённой записи возвращает то же задание. Клиент блокирует двойное нажатие.

- GET /api/youtube/jobs/:id — состояние.
- DELETE /api/youtube/jobs/:id — отмена активного или удаление готового.
- DELETE /api/youtube/jobs/request/:requestId — отмена даже до завершения POST; отметка не даёт позднему POST запустить работу.
- GET /api/youtube/jobs/:id/file — поток attachment, без полного файла в памяти/Blob.

Задание: id, requestId, kind, videoId, formatId, outputFormat, subtitleTrackId, status, step, progress, error, expiresAt, result. result доступен только для ready: filename/bytes/ext/height (null у аудио и субтитров). expiresAt/retryAt — миллисекунды Unix.

Статусы: preparing/downloading/processing/cancelling/ready/cancelled/failed/expired. step различает дорожки, объединение, конвертацию и проверку. Процент относится к текущему потоку и показывается только при известных/примерных данных. Объединение/конвертация/субтитры не получают выдуманный процент.

Ошибка HTTP: {apiVersion:1,error:{code,message,requestId,retryAt?}}. Ошибка задания: error:{code,message,retryAt?}. Чужое или неизвестное задание — 404, истёкший файл — 410. Повторное сохранение исчезнувшего результата предлагает создать его заново.

## Ошибки и жизненный цикл

Отмена имеет отдельное состояние ожидания ответа API. Повторное создание в это время и повторная проверка готового файла блокируются. Прерывается дерево процессов yt-dlp/FFmpeg; файлы удаляются после завершения. Неподтверждённая отмена при потере сети показывается как ошибка, можно повторить отмену. Серверный тайм-аут ограничивает оставшуюся работу.

Смена/очистка ссылки и переход на другую страницу отменяют активную работу. «Очистить» заблокирована при получении сведений; отдельная отмена запроса остаётся. Старые ответы не возвращают прежний результат. На закрытие/перезагрузку pagehide отправляет отмену с keepalive. Доставка зависит от браузера/сети; серверный тайм-аут остаётся запасным ограничением. При возврате/повторном открытии новый download сам не создаётся. История заданий не восстанавливается.

При ошибке опроса клиент пробует отменить задание, показывает конечную ошибку и допускает повтор после восстановления связи. Если прежнее задание исчезло вместе с перезапуском API/сессией, это не блокирует новое скачивание.

При ошибке/отмене файлы очищаются, состояние хранится около минуты. Готовые файлы удаляются после TTL; очистка каждые 10 секунд. Уже начатая выдача браузеру завершается до удаления. Готовность сервера не означает завершение сохранения на устройство — оно отображается браузером. Range/возобновление пока не поддерживается.

После остановки API активные задания отменяются; после аварийного перезапуска очищаются каталоги UUID. Второй API защищён lock-файлом. Готовые результаты/список заданий не переживают перезапуск; прежняя ссылка становится недоступной. Невалидный lock требует ручной проверки.

## Субтитры и HTTP 429

yt-dlp получает свежие сведения; выбранный текст загружается Node HTTP потоком. Разрешены только HTTPS youtube.com/www.youtube.com /api/timedtext и video.google.com /timedtext, без произвольного URL клиента и редиректов. Подписанный адрес остаётся на сервере. Промежуточный --load-info-json удалён.

Проверяются UTF-8, заголовок VTT и интервалы. Пустая реплика допустима, но дорожка в целом должна содержать текст. При конвертации сохраняются текст и временные интервалы, оформление/служебные теги VTT могут отличаться в SRT. Имя содержит код языка и author/auto.

HTTP 403/404/429, ошибка сети, тайм-аут, неверный формат, запись файла и сбой FFmpeg различаются. На 429 включается общий cooldown для заданий субтитров, сохраняемый в .youtube-downloads/.subtitle-cooldown.json. retryAt/Retry-After и таймер кнопки предотвращают частые повторы; автоматического повтора нет. Локальная пауза не гарантирует снятия ограничения YouTube. Cookies, обход, смена IP и авторизация не добавлялись.

## Хранение и границы

Результаты принадлежат cookie сессии: UUID не даёт доступа другой сессии. Каталоги — только проверенные непосредственные UUID-потомки .youtube-downloads. Имя очищается, Content-Disposition поддерживает Unicode. Установщики/результаты/временные файлы/.env исключены из Git; исходные медиаактивы проекта не запрещаются глобальными масками.

API проверяет схему/хост/ID и строит канонический watch URL. Конфиги/плагины/импорт cookies/удалённая догрузка компонентов yt-dlp отключены. Географические и авторизационные ограничения не обходятся. За Vite proxy посетители могут делить один адрес лимитера; X-Forwarded-For не считается доверенным.

Для публичного worker потребуются отдельные аутентификация, сетевая изоляция/egress-политика и архитектура размещения. Публикация не выполнялась.

[Единый сценарий ручной приёмки](youtube-acceptance.md). Этот документ описывает поведение, а не результаты проверок. Сборка, линтер, тесты, API, браузер и скачивания агентом не запускались.
