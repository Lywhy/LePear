# LePear

LePear — веб-приложение для визуального проектирования темы сайта на основе **shadcn/ui**. Редактор позволит подбирать цвета, типографику и параметры компонентов, сразу видеть результат на UI-блоках и экспортировать тему для своего сайта.

## Текущее состояние

Главная страница содержит статичный макет редактора, навигацию, мобильное меню, блоки возможностей, шаги работы и FAQ. Изменение темы и экспорт доступны отдельно на `/editor`. Визуальное направление вдохновлено Surfsky; фоновая иллюстрация создана для LePear.

Установлен shadcn/ui Nova на Base UI, настроены CSS-переменные, шрифт Geist и alias `@`. Редактор позволяет менять режим, акцент, шрифт, размер текста и радиус, копировать или скачивать CSS-переменные, скачивать JSON. Настройки изолированы от главной страницы. Автоматическое сохранение и импорт пока не реализованы; пример приглашения не отправляет данные.

## Планируемые возможности

- Светлая и тёмная темы с независимыми настройками цветов.
- Готовые пресеты, выбор акцентного и семантических цветов.
- Выбор шрифта, размеров текста, начертаний и интервалов.
- Настройка закруглений, высоты элементов, отступов и плотности компонентов.
- Живой предпросмотр компонентов и составных блоков на разных ширинах экрана.
- Локальное сохранение и переключение пользовательских тем.
- Импорт и экспорт JSON, экспорт CSS-переменных для подключения к сайту.

В MVP настройки будут храниться в браузере. Аккаунты, серверное хранение и совместное редактирование в текущий объём не входят. Применение темы к другому сайту предполагается через экспорт.

## Локальный запуск

Понадобятся Node.js, совместимый с установленной версией Vite, и pnpm.

```sh
pnpm install
pnpm dev
```

По умолчанию приложение доступно по адресу http://localhost:5173. Если порт занят, Vite может выбрать следующий свободный порт — точный адрес выводится в терминале.

### Импорты через alias

Alias `@` указывает на `src`. Он настроен в Vite, `tsconfig.json` и `tsconfig.app.json`.

```tsx
import App from '@/App.tsx'
```

После добавления компонентов shadcn/ui импорты будут использовать ту же схему, например `@/components/ui/button`.

## Контактная форма

Страница `/contact` использует компоненты shadcn/ui Base Nova: Button, Card, Dialog, Input, Label и Textarea. Стили страницы и формы написаны на Tailwind.

Форма проверяет обязательные поля, email, имя и длину сообщения. Без обработчика отправки она открывает предварительный просмотр и явно сообщает, что сообщение не отправлено. Данные не сохраняются и не передаются на сервер.

Переиспользуемый компонент: `src/components/contact-form.tsx`. Для реальной отправки передайте асинхронный обработчик `onSend(values)`; компонент показывает состояние ожидания, обрабатывает ошибку и очищает поля только после успешной отправки. API обратной связи пока не подключён.

## Оформление и страницы

Все стили интерфейса заданы utility-классами Tailwind в TSX. Отдельного файла стилей лендинга нет. `src/index.css` содержит подключение Tailwind, тему и базовые токены shadcn. Динамические CSS-переменные в предпросмотре необходимы для изменения темы; отдельные CSS-правила для макета не используются.

- `/` — главная со статичным макетом без активных полей и кнопок внутри превью.
- `/editor` — настройки, живые компоненты и скачивание CSS/JSON.
- `/contact` — контактная форма в режиме предпросмотра.

Экспорт CSS создаёт класс `.lepear-theme`, который нужно назначить контейнеру в приложении shadcn/ui с Tailwind CSS v4. Шрифт Geist требует подключения `@fontsource-variable/geist`. Выгружается один выбранный режим темы. JSON содержит версию формата и текущие настройки; импорт пока не реализован.

## MCP и порядок разработки

shadcn MCP использует установленный в проекте CLI и запускается с рабочей папкой LePear. Конфигурация проекта хранится в `.codex/config.toml`; на текущем компьютере сервер также добавлен в пользовательский config.toml Codex, чтобы он был доступен из чата вне папки проекта.

Через `components.json` доступны реестры:

- shadcn/ui — стандартный реестр, отдельная запись не требуется;
- `@react-bits` → `https://reactbits.dev/r/{name}.json`;
- `@reui` → `https://reui.io/r/{style}/{name}.json`; `{style}` соответствует `base-nova`.

После изменения конфигурации перезапустите Codex, чтобы загрузить MCP-сервер. Если проект переместится, обновите `cwd` и абсолютный путь в пользовательской конфигурации.

Разработка идёт по issues Linear. По просьбе пользователя агент не запускает сборку, тесты, линтер или проверку в браузере. Пользователь выполняет ручную приёмку; issue закрывается после его подтверждения. Правила сохранены в `AGENTS.md`.

## Модель темы v2 (MYT-7)

Единый формат описан в `src/lib/site-theme.ts`:

- `version: 2` — версия схемы;
- `mode` — выбранный режим;
- `palettes.light` и `palettes.dark` — независимые палитры токенов shadcn;
- `typography` — шрифт, базовый размер, масштаб заголовков, веса, межстрочный и межбуквенный интервалы;
- `shape.radius` — базовое закругление;
- `layout` — минимальная высота контролов, внутренние горизонтальные отступы, отступы и промежутки компонентов.

Типографика, форма и размеры общие для обоих режимов. Цветовые изменения затрагивают только текущий режим. При изменении основного акцента по умолчанию также обновляются цвет текста основной кнопки и focus ring.

`themeLimits` — общий источник диапазонов и шагов. `validateTheme(unknown)` возвращает либо отдельную копию корректной темы, либо ошибки с путями полей. Значения не приводятся к нужному типу и не обрезаются автоматически. Проверяются версия, режим, формат цветов, доступность шрифта, конечность чисел, диапазоны и шаги. Неизвестные поля не переносятся в результат. Предыдущая схема v1 не принимается как v2; импорт и миграции остаются отдельной задачей.

`updateTheme()` объединяет изменения с текущей темой и валидирует весь результат. При ошибке редактор сохраняет предыдущую тему и сообщает причину. `createInitialTheme()` создаёт новые объекты для полного сброса обоих режимов.

`themeTokens()` сопоставляет модель с переменными shadcn и дополнительными токенами типографики/размеров. `previewStyle()` задаёт их только контейнеру предпросмотра. Внутри него используется `data-theme`, чтобы светлый предпросмотр не наследовал dark-варианты оболочки редактора. Статичный макет главной использует отдельную исходную тему.

Текущая панель управляет режимом, основным акцентом, шрифтом, размером текста и радиусом. Дополнительные поля уже представлены в модели и привязаны к предпросмотру; их панели будут добавлены в MYT-10 и MYT-11. CSS-экспорт содержит выбранный режим, JSON — всю модель v2 с обеими палитрами.

Приёмка MYT-7 выполняется пользователем. Сборка, тесты и браузерная проверка после изменения модели агентом не запускались.

## Каталог предпросмотра (MYT-8)

На `/editor` доступны два режима ширины: «Широкий» использует доступное пространство, «Узкий» ограничивает макет до 390 px. При меньшей ширине экрана область сжимается до доступного места. Раскладка редакторского предпросмотра использует container queries, поэтому колонки зависят от ширины самого макета, а не всего окна.

Под составным блоком находится каталог компонентов:

- вкладка «Компоненты» — варианты кнопок, отключённая кнопка, поле email с ошибкой после применения, Select роли, Checkbox, Switch, отключённое поле и Dialog;
- вкладка «Таблица» — демонстрационные проекты, выбор строк, локальное архивирование и восстановление исходных записей;
- диалог — редактирование названия проекта и валидация пустого/короткого значения, сохранение только в примере.

Примеры не выполняют сетевых запросов и не изменяют реальные проекты. Выбранные состояния сохраняются при переключении ширины предпросмотра, но не сохраняются после перезагрузки страницы или выхода из каталога.

Для SelectContent и DialogContent добавлен необязательный `portalContainer`. В редакторе он указывает на контейнер текущей темы: выпадающий список и диалог наследуют палитру и шрифт предпросмотра. В узком виде максимальная ширина диалога также ограничена. Использование этих компонентов на других страницах не требует нового параметра.

Статичный макет главной не содержит каталог, интерактивные контролы или диалог. Стили остаются в Tailwind; новые CSS-файлы не добавлены.

Ручная приёмка MYT-8:

1. Переключить широкий/узкий вид на `/editor` и обратить внимание на перестроение колонок и горизонтальную прокрутку только внутри таблицы.
2. Изменить тему, шрифт и радиус; открыть список ролей и диалог в светлом и тёмном режимах.
3. Пройти элементы клавишей Tab, проверить focus/hover и отключённые элементы.
4. Нажать «Применить» без email, затем ввести корректный email. Переключить Checkbox, Switch и Select.
5. Открыть диалог: проверить ошибку короткого названия, отмену, сохранение и закрытие Escape.
6. Во вкладке таблицы выделить одну/все строки, архивировать их в примере и восстановить.
7. Убедиться, что главная сохранила статичное превью.

Сборка, тесты, линтеры и проверка в браузере агентом не запускались. Задача ожидает пользовательской приёмки.

## Палитры и редактор цветов (MYT-9)

На `/editor` доступны четыре полных цветовых пресета: «Лес», «Океан», «Слива», «Графит». У каждого свои светлая и тёмная палитры. Пресет применяется одним обновлением ко всем цветам **выбранного режима**; типографика, размеры и цвета второго режима сохраняются. Совпадение с пресетом определяется по всем цветам, после ручного изменения отображается «Своя палитра».

Группы настроек включают фон и поверхности карточек/меню, основной и приглушённый текст, основной и вторичный цвета кнопок, выделение/наведение, ошибки, границы полей и кольцо фокуса. Для каждого цвета доступны системный picker и ручной HEX. Поддерживается `#RRGGBB`, дополнительно `#RRGGBBAA` с прозрачностью (кроме основного акцента). Picker меняет RGB, сохраняя существующую прозрачность. Корректное значение сразу применяется, некорректное остаётся черновиком с ошибкой и не попадает в модель/экспорт. Escape отменяет черновик.

При изменении основного акцента автоматически выбирается более контрастный текст между белым и `#111811`, кольцо фокуса принимает цвет акцента. После этого оба токена можно изменить отдельно. Пресет передаёт собственные согласованные значения без автоматического переопределения.

«Исходные цвета режима» возвращает палитру «Лес» только для выбранного режима. «Сбросить всю тему» по-прежнему возвращает оба режима и все общие параметры. Неприменённые ошибочные черновики очищаются при выборе пресета, сбросе и смене режима.

Подсказки читаемости рассчитывают контраст текстовых пар (ориентир 4.5:1) и кольца фокуса относительно фона (3:1), включая альфа-композицию. Для прозрачного корневого фона расчёт использует чёрную/белую подложку выбранного режима, поэтому фактический фон окружения может изменить результат. Это не полная проверка доступности: hover, disabled, наложения, прозрачные диалоги и реальные фоновые слои требуют ручной оценки. Подсказки не блокируют пользовательские цвета.

Ручная приёмка:

1. В тёмном режиме выбрать «Океан», изменить фон/текст. Перейти в светлый, выбрать «Слива», затем вернуться: настройки режимов должны оставаться независимыми.
2. Изменить шрифт/размер/радиус, выбрать любой пресет: эти общие настройки должны сохраниться. Кнопка пресета выделяется только при полном совпадении палитры.
3. Ввести корректный HEX и значение с альфой, затем некорректное `#XYZ`: предпросмотр и CSS/JSON должны содержать последний корректный цвет. Escape возвращает его в поле. Для акцента альфа недопустима.
4. Изменить основной акцент, увидеть автоматический текст кнопки и кольцо фокуса; затем изменить их отдельно. Задать одинаковые фон/текст: должна появиться подсказка контраста.
5. Проверить все группы цветов в широком/узком предпросмотре, включая hover/focus, ошибки формы, открытые Select и Dialog.
6. Проверить сброс цветов текущего режима и сброс всей темы. Убедиться, что палитра редактора и статичная главная не зависят от изменений предпросмотра.

Сборка, тесты, линтеры и браузерная проверка агентом не запускались. Новых зависимостей и CSS-файлов не добавлено.

## Типографика (MYT-10)

В настройках `/editor` есть отдельная группа типографики:

- Шрифт: Geist (локальный variable с кириллицей через уже подключённый `@fontsource-variable/geist`), системный, Georgia. У каждой опции показан источник и fallback. Для Geist цепочка: Geist Variable → system-ui → Arial → sans-serif; для системного: system-ui → Segoe UI → Arial → sans-serif; для Georgia: Georgia → Times New Roman → serif. Системные шрифты не скачиваются. Их доступность и промежуточные насыщенности зависят от устройства.
- Базовый размер 14–20 px, шаг 1.
- Масштаб заголовков 1.1–2, шаг 0.05; подзаголовки используют промежуточный коэффициент `1 + (scale - 1) / 2`.
- Насыщенность текста и заголовков отдельно: 300–700, шаг 100.
- Межстрочный интервал 1.2–2, шаг 0.05; межбуквенный −0.03–0.1 em, шаг 0.005.

Все параметры используют существующие ограничения модели. Slider округляет дробные значения до трёх знаков перед передачей модели. Настройки общие для обоих режимов; «Сбросить типографику» сохраняет палитры, радиус и отступы.

В предпросмотр добавлен текстовый образец с кириллицей, латиницей, цифрами и длинной подписью кнопки. Текст форм, кнопок, карточек, таблицы, Select и Dialog использует общие настройки семейства/насыщенности/интервалов. Размеры мелких подписей рассчитываются от базового с минимумом 14 px; абсолютные токены предотвращают повторное уменьшение вложенных Badge. Длинные подписи допускают перенос; таблица сохраняет внутреннюю прокрутку. Однострочный Input остаётся однострочным, длинное значение прокручивается внутри поля.

CSS-экспорт содержит семейство и fallback, параметры типографики и производные `--preview-small-size`, `--preview-heading-size`, `--preview-subheading-size`. JSON сохраняет исходные параметры. В стороннем проекте токены `--preview-*` нужно привязать к собственным компонентам; экспорт не поставляет файлы Geist.

## Размеры и отступы (MYT-11)

Группа «Размеры и отступы» на `/editor` управляет общими для обоих режимов параметрами:

| Параметр | Диапазон | Применение |
| --- | --- | --- |
| Радиус | 0–24 px | Карточки/диалоги/меню: полный; кнопки/поля/пункты меню: 70%; Badge и мелкие детали: 50%. Switch остаётся овальным, аватары — круглыми. |
| Минимальная высота контролов | 40–64 px | Кнопки, поля, Select и его пункты. Таблица использует ту же минимальную высоту строк. |
| Горизонтальный отступ контролов | 8–32 px | Кнопки, поля, пункты меню и ячейки таблицы. |
| Внутренний отступ блоков | 12–40 px | Карточки, диалог, шапка и основная область предпросмотра. |
| Расстояние между элементами | 8–32 px | Сетки, группы действий, формы и промежутки блоков. |

Все ползунки используют шаг 1 и общие ограничения модели. Варианты плотности применяются одним обновлением к четырём параметрам `layout`: «Компактно» (40/8/12/8), «Обычно» (44/12/20/16), «Просторно» (56/24/32/24). Радиус и типографика сохраняются. Произвольное сочетание отображается как «Своя плотность».

Значение высоты — минимум, а не фиксированная высота. Вертикальный отступ контролов вычисляется как половина расстояния между элементами с ограничением 4–12 px. Расчётный безопасный минимум: `ceil(max(controlHeight, fontSize * lineHeight + 2 * paddingBlock + 2))`. Дополнительные 2 px учитывают границы. В панели показано расчётное значение; при крупном тексте оно может превышать запрошенные 64 px. Многострочные кнопки/Select могут расти ещё выше; поля Input остаются однострочными. Горизонтальный Select отключает фиксированную высоту базового shadcn-компонента только в предпросмотре.

Checkbox/Switch сохраняют размер визуального индикатора; строки формы с ними получают безопасную минимальную высоту. Толщина границ, тени и служебные иконки не являются новыми глобальными настройками. Меняются только компоненты предпросмотра — панель управления не зависит от этих токенов. Главная сохраняет статичный характер.

«Сбросить размеры» возвращает `shape` и `layout` к исходным значениям без изменения палитр и типографики. CSS содержит исходную высоту `--preview-control-height`, производные `--preview-control-safe-height` и `--preview-control-padding-block`, отступы и радиус. JSON сохраняет исходные параметры; схема остаётся v2. В собственных компонентах нужно использовать безопасную высоту как `min-height`, а не как фиксированную высоту.

Ручная приёмка:

1. Переключить три плотности, затем изменить отдельные ползунки: проверить индикацию своей плотности и сохранение радиуса/типографики.
2. Изменить каждый параметр от минимума до максимума. Посмотреть карточки, кнопки, поля, Tabs, Select, открытый диалог и таблицу.
3. Совместить минимальную высоту с размером текста 20 px и line-height 2: расчётный минимум должен увеличиться. Длинные подписи должны переноситься, без фиксированной обрезающей высоты.
4. В узком виде проверить сочетание максимальных отступов и крупной типографики, длинную кнопку образца, поля/меню/диалог; таблица прокручивается внутри.
5. Сбросить размеры: палитры и типографика должны сохраниться. Переключить режим и цветовой пресет: размеры должны сохраниться.
6. Посмотреть CSS/JSON и проверить, что панель управления остаётся читаемой, а на главной нет новых интерактивных контролов.

## Локальные темы и восстановление состояния (MYT-12)

Редактор автоматически сохраняет рабочее состояние в `localStorage` под ключом `lepear.workspace` (версия оболочки 1, тема schema v2). Восстанавливаются обе палитры, выбранный режим, типографика, размеры, ширина и вид предпросмотра, раскрытые верхние группы настроек. Сохранение выполняется после изменения рабочего состояния. Черновики некорректного HEX, несохранённое название копии и демонстрационные данные форм/таблицы не записываются.

В блоке «Мои темы» можно:

- Создать именованную копию текущей темы, включая оба режима и общие настройки. До 20 копий; название 1–60 символов, без дубликатов независимо от регистра.
- Выбрать копию для работы. Выбор другой темы заменяет рабочий вариант, поэтому отдельные варианты нужно заранее сохранить копиями.
- Изменять рабочую тему без автоматической перезаписи выбранной копии. При отличиях показано пояснение; «Обновить копию» явно записывает рабочую тему в выбранную копию.
- Переименовать выбранную копию или удалить её. Удаление оставляет текущую рабочую тему в черновике. Сброс всей темы не удаляет библиотеку копий.

Копии хранят независимые снимки. Перезагрузка сохраняет и восстанавливает рабочие изменения, даже если выбранная именованная копия ещё не обновлена. Статус внизу панели показывает результат записи. Если браузер запрещает хранилище или превышена квота, редактор продолжает работать в памяти; доступны повтор сохранения и скачивание JSON текущей темы.

Данные читаются как unknown: валидируются версия оболочки, каждая тема через `validateTheme`, идентификаторы/уникальные названия, ссылка на выбранную тему и настройки интерфейса. Ограничение размера чтения — 1 млн символов. Повреждённые или неподдерживаемые данные приводят к исходному состоянию с предупреждением; автозапись приостанавливается, чтобы не затереть старые данные. Кнопка «Заменить повреждённые данные текущими» явно разрешает их замену. Автоматической миграции старых схем пока нет.

Хранилище зависит от браузера и origin: другой протокол, домен или порт имеет отдельные данные. Очистка данных сайта удаляет библиотеку. Синхронизации между устройствами и вкладками нет; при параллельном редактировании последняя запись выигрывает. JSON-экспорт содержит текущую тему, а не всю библиотеку. Для важных вариантов скачивайте отдельные резервные копии.

Ручная приёмка:

1. Настроить разные палитры двух режимов, типографику и размеры; поменять ширину/вид, свернуть группы. Перезагрузить `/editor`: рабочее состояние должно восстановиться.
2. Создать две именованные копии с разными настройками. Переключать их и проверить независимость снимков.
3. Изменить выбранную тему, перезагрузить до обновления копии: рабочие изменения должны восстановиться. Нажать «Обновить копию», выбрать другую и вернуться.
4. Проверить пустое/повторяющееся название, переименование, удаление копии (рабочий вариант остаётся), глобальный сброс (остальные копии остаются).

Должны появиться исходная тема и предупреждение; исходные данные не меняются до явной замены. При необходимости восстановить резервное значение.

## Импорт и экспорт темы (MYT-13)

В редактор добавлен импорт из JSON-файла или текстового поля (до 1 МБ). Принимается объект темы schema v2 — тот же формат, который скачивается и копируется из редактора. Наличие версии и все цвета/шрифты/числа/диапазоны/шаги проверяются через общий `validateTheme`; неподдерживаемые версии не мигрируются. Ошибки показываются до применения и не меняют рабочее состояние. Есть краткий предварительный просмотр параметров и явная кнопка «Применить тему».

Применение заменяет рабочую тему атомарно, переводит её в черновик и сохраняет через существующий механизм автосохранения; именованные копии не меняются. При заблокированном localStorage импорт продолжает работать в памяти. Асинхронное чтение файла защищено от запоздалого результата после выбора другого файла, вставки текста или очистки. CSS и JSON всей локальной библиотеки не являются форматами импорта.

CSS-экспорт теперь содержит **обе независимые палитры**, общие и производные токены типографики/размеров, `@theme inline` с цветовыми и радиусными соответствиями Tailwind v4 и scoped-правила для компонентов shadcn. Корень `.lepear-theme` использует выбранный режим по умолчанию; `[data-theme="light"]` и `[data-theme="dark"]` явно выбирают палитру. Для dark-вариантов компонентов переключайте также класс `.dark`. Переменные ограничены контейнером темы. Полезные классы `.lepear-stack` и `.lepear-grid` подключают настраиваемые промежутки к составным блокам; в собственных раскладках используйте эти классы или соответствующие токены.

Сгенерированный файл — исходный CSS для обработки Tailwind v4. Его нужно импортировать в основной stylesheet после Tailwind/shadcn; для Geist подключить пакет шрифта отдельно. Порталы Select/Dialog должны быть внутри контейнера темы, иначе они не наследуют его переменные. UI редактора и комментарий экспортированного CSS объясняют подключение.

Доступны скачивание и копирование CSS/JSON. При недоступности Clipboard API появляется read-only поле для ручного копирования (выделение при фокусе), остаётся скачивание. JSON содержит обе палитры и все исходные параметры, не библиотеку копий. Ранее описанный экспорт только выбранной палитры заменён новым экспортом обоих режимов.

Минимальный пример React/shadcn и пошаговая инструкция находятся в `examples/theme-integration/`. Он не включён в маршруты и не запускался агентом. Пользователю нужно подключить скачанный CSS и вручную проверить интеграцию в выбранном проекте.
