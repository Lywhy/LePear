# LePear: правила работы агента

## Задачи

- Разрабатывать приложение последовательно по issues Linear. Перед изменениями прочитать выбранную задачу и её критерии приёмки.
- Сохранять согласованные ограничения: shadcn/ui Base Nova, Tailwind utility-классы в TSX, статичное превью на главной, рабочий редактор на отдельной странице /editor.
- Для поиска и использования компонентов предпочитать shadcn MCP. Основной реестр shadcn доступен по умолчанию; React Bits и ReUI подключены в components.json.
- React Bits: namespace @react-bits. Выбирать варианты TypeScript + Tailwind, когда они доступны.
- ReUI: namespace @reui; стиль берётся из components.json (base-nova). Не устанавливать npm-пакеты @reui/* вместо элементов реестра.
- Не добавлять анимационные зависимости без потребности конкретной задачи. Учитывать prefers-reduced-motion.

## Приёмка пользователем

- Пользователь самостоятельно проверяет и принимает выполненные задачи.
- Без отдельной просьбы пользователя НЕ запускать сборку, тесты, линтеры, браузерную/визуальную проверку и не создавать автоматические QA-отчёты.
- Не добавлять тесты без отдельного согласования с пользователем.
- Чтение исходников, документации, criteria и конфигурации для выполнения задачи разрешено; запрет относится к проверочным прогонам и приёмке результата.
- После реализации кратко сообщить, что изменено, и какие пункты пользователю проверить вручную. Явно указать, что проверки не запускались.
- Не отмечать issue как Done самостоятельно. После реализации сообщить готовность к ручной проверке и дождаться подтверждения пользователя перед закрытием задачи в Linear.
- Не утверждать, что сборка, тесты или функциональность проверены, если проверки не выполнялись.
